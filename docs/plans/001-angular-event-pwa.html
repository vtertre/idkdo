  1. Open / on the web app.
  2. Enter an Event name and submit.
  3. The browser posts to /api/events and navigates to /events/:eventId.

  • Components use one frontend Event repository; they never inject HttpClient.
  • Shared Zod schemas validate API success and error payloads at the browser boundary.

Decisions the executor must preserve

Framework version Latest stable Angular 22.x patches available when execution begins. Angular compatibility requires Node 22.22.3+, 24.15+, or 26 and TypeScript 6.0. This plan standardizes the repository on the operator's Node 24.17 line.
Application model Standalone APIs, Angular's default zoneless and OnPush behavior, native signals, and stable Signal Forms. This matches current Angular defaults and uses Angular 22's stable Signal Forms API without adding a state library.
API access One feature-local EventRepository wraps HttpClient and shared Zod parsing. Components remain presentation-focused and no unused cross-feature service layer is introduced.
API origin Use relative /api URLs. The dev server proxies /api to http://localhost:3000. This avoids CORS changes and makes the deep link use the web application's current origin.
Routes Eagerly load / for Event creation and /events/:eventId for Event entry; redirect unknown routes to /. Both small pages are primary landing surfaces. Angular recommends eager loading primary landing pages; later, heavier feature routes can be lazy-loaded.
Projection lag Retry GET only for 404, up to four retries with short increasing delays; surface a clear not-found state after exhaustion. A just-created Event may not yet exist in the read projection. Do not retry validation errors, server errors, or malformed success payloads.
PWA cache policy Asset groups only, no API dataGroups, and an explicit !/api/** navigation exclusion. Angular service-worker configuration supports explicit asset and navigation rules. API data must always use the network.

Version drift rule: install the latest stable 22.x patch available when execution begins and keep all Angular framework packages on the same major/minor line. 4. Write the creation-page tests, then ship the create flow

  1. Create a model signal containing { name: "" }, wrap it with form(), and bind the input with FormField from @angular/forms/signals. Do not use ReactiveFormsModule, FormControl, or FormGroup.

  5. Test that a valid submit calls the Event repository once and navigates to /events/<returned-id>.
  6. Test double-submit prevention while the request is pending.
  7. Test that a rejected request keeps the user on the form, re-enables submission, preserves the entered name, and shows the normalized error in an aria-live region.
  8. Keep non-form page state in signals and use the router directly. Do not add an Event feature service between the page and repository.
